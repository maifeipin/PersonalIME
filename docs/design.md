# 私人输入法设计文档

- 版本：0.1
- 状态：初始设计
- 目标平台：Windows 11（首版）

## 1. 产品目标

做一个本地优先、可由个人掌控的中文输入法。用户可以使用拼音、五笔或自己维护的编码词条；输入法记住用户的选择习惯，让常用词和常用输入方式逐步排到前面。

### 设计原则

1. **用户词条优先**：明确添加的自定义词条始终可查、可编辑；可选“置顶”以固定在候选列表前部。
2. **越用越顺手**：已选择词条的次数和近期使用情况影响排序，但不会覆盖用户的手动排序。
3. **本机可控**：输入内容、词库和学习记录默认只写入本机；可查看、清除、导出和导入。
4. **输入方式可选**：拼音、五笔可独立开关；自定义词条可同时参与两种模式，也可指定只在某种模式中出现。

## 2. 用户与典型流程

### 输入

1. 用户在任意文本框中切换到本输入法。
2. 按快捷键选择拼音或五笔模式，输入编码。
3. 引擎展示带序号的候选词；用户按数字键、空格或翻页键选择。
4. 提交后更新该词的使用统计，后续排序更贴合个人习惯。

### 管理词条

用户打开词库管理器后可以：

- 添加词条：填写词语、拼音编码、五笔编码，以及可选备注和适用模式。
- 删除词条：删除用户维护的词条；内置基础词典不可在管理器中直接删除。
- 自定义顺序：通过上移、下移或拖动调整顺序；可将词条置顶。
- 搜索与编辑：按词语或编码查找，修改已有条目。
- 导入与导出：使用带版本号的 JSON 文件备份个人词条和排序设置。

## 3. 功能范围

### 首版必须支持

- Windows 11 桌面输入，接入标准文本输入框。
- 拼音输入和五笔输入；模式可切换，候选可翻页。
- 用户词条的新增、编辑、删除、置顶和手动排序。
- 基于选择历史的自适应候选排序。
- 本机 SQLite 存储、词库 JSON 导入/导出、清空学习记录。
- 设置页面：启用的输入模式、默认模式、模式切换快捷键、候选数量。

### 首版暂不处理

- 云同步、账号体系、联网学习和遥测。
- 手写、语音、英文预测、跨平台支持。
- 完整的开放词库编辑器和自动从云端更新词典。

## 4. 交互设计

### 输入模式

- 默认提供“拼音”和“五笔”两种模式，通过可配置快捷键切换；系统托盘菜单也可切换。
- 模式状态通过输入法语言栏/状态图标呈现。
- 用户词条可标记为“拼音和五笔均可用”“仅拼音”或“仅五笔”。
- 候选窗口展示当前编码、候选词、序号和必要时的词条来源标记。常规使用不显示复杂分数。

### 候选操作

- `1–9`：选择对应候选。
- `Space`：选择首选候选；无候选时按当前配置上屏空格。
- `Up/Down`：移动高亮项；`PageUp/PageDown`：翻页。
- `Esc`：取消当前组合串；`Backspace`：删除编码末尾字符。
- `Enter`：按配置提交组合串或选中的候选。

具体按键需允许配置，避免和用户现有快捷键冲突。

## 5. 输入与编码处理

### 拼音

- 首版支持全拼；输入串按拼音音节切分，允许连续输入后生成短语候选。
- 基础词典提供常见字词映射；用户词典可增加个人姓名、术语和固定表达。
- 模糊音、双拼和拼音纠错作为后续扩展，不作为首版承诺。

### 五笔

- 首版明确采用 **86 版五笔**，编码表与拆字/词组规则作为版本化资源随程序发布。
- 输入引擎按编码查询字词，用户词条可补充内置词典中没有的编码。
- 98 版或新世纪版作为后续可选方案，避免首版不同版本编码混用。

### 自定义编码

每条用户词条至少包含词语和一个编码。拼音、五笔编码可只填其一，也可同时填写。编码按其所属模式解析，不将两种编码混为一类。

## 6. 候选排序与个人习惯

排序采用分层规则，保证显式设置的确定性：

1. 用户置顶词条按用户指定顺序显示。
2. 非置顶候选先按上下文匹配和输入编码匹配质量过滤/排序。
3. 同等匹配质量下，结合用户手动顺序、使用频率和近期使用情况排序。
4. 分数相同则按稳定的词条 ID 排序，避免候选每次跳动。

建议首版使用可解释的平滑评分：

```text
score = match_score
      + personal_order_bonus
      + frequency_weight * log(1 + selected_count)
      + recency_weight * exp(-age_days / decay_days)
```

- `match_score`：编码匹配质量、词语边界和短语匹配情况。
- `personal_order_bonus`：用户设置的排序位置；置顶词条单独处理，不靠分数模拟。
- `selected_count`：用户实际提交该候选的累计次数。
- `age_days`：距上次选择的天数；近期使用会暂时增加权重。
- 衰减参数可配置为内部默认值，后续通过实际使用反馈调整。

学习只在用户明确提交某个候选后发生。取消组合串、浏览候选、未选词条不增加频次。系统应记录计数和最近选择时间，不记录完整输入句子。用户可以按词条重置统计或一次清空全部学习数据。

### 防止排序意外

- 手动顺序优先于自动学习；自动排序不能把置顶词条挤走。
- 使用次数更新采用平滑计分，避免一次偶然选择大幅改变顺序。
- 对长尾候选设衰减，使近期习惯能逐步纠正旧偏好。
- 词条删除时同时删除其统计数据；导入时提供“合并”或“替换”策略。

## 7. 技术架构

### 首版建议

- **输入法接入层**：Windows Text Services Framework（TSF），负责焦点、组合串、候选窗口和文本提交。
- **输入引擎**：独立 C++ 核心库，提供编码解析、词典查询、候选排序和学习更新接口。
- **词库管理器**：轻量 Windows 桌面设置界面；通过本地服务/共享核心库读写词库。
- **本地数据**：SQLite 保存用户词条、使用统计与偏好；只读词典资源单独版本化。
- **备份格式**：带 schema 版本的 UTF-8 JSON；导入先校验，再在事务中写入。

```text
应用文本框
    ↕ TSF
输入法接入层 ─── 候选界面
    ↕
输入核心（拼音 / 五笔 / 词库合并 / 排序）
    ↕
SQLite 用户数据 + 版本化内置词典
    ↕
词库管理器与 JSON 备份
```

输入引擎不依赖 UI，便于后续写独立命令行调试器或替换管理器界面。TSF 与核心库之间使用窄接口，避免平台层逻辑污染编码和排序实现。

## 8. 数据模型

### `user_entries`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT/UUID | 稳定主键 |
| `phrase` | TEXT | 词语 |
| `pinyin_code` | TEXT nullable | 拼音编码（规范化小写） |
| `wubi86_code` | TEXT nullable | 86 版五笔编码（规范化小写） |
| `mode_mask` | INTEGER | 可用模式位掩码 |
| `pinned` | INTEGER | 是否置顶 |
| `manual_order` | INTEGER | 用户手动顺序，数值越小越靠前 |
| `created_at` / `updated_at` | INTEGER | Unix 时间戳 |

### `entry_stats`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `entry_id` | TEXT/UUID | 对应词条 |
| `selected_count` | INTEGER | 提交次数 |
| `last_selected_at` | INTEGER nullable | 最近提交时间 |

### `settings`

存储启用模式、默认模式、快捷键、候选数量、排序参数和数据 schema 版本。设置项须有默认值和迁移策略。

## 9. 非功能要求

- 常见短编码查询与候选刷新应保持即时响应；候选排序不得阻塞文本提交。
- SQLite 写操作使用事务；核心数据库损坏时保留可恢复的最近备份。
- 用户数据默认仅本地保存；导出文件明确包含哪些字段。
- 所有用户输入都按普通文本处理，不运行编码或导入文件中的内容。
- 安装和卸载需正确注册/注销 TSF 服务，并保留用户词库的可选导出能力。
- 版本升级提供数据库迁移；迁移失败时回滚并提示恢复路径。

## 10. 模块边界

```text
ime-core/
  encoding/       拼音分词、五笔码处理
  dictionary/    内置词典、用户词库查询与合并
  ranking/       手动顺序、频次、近期偏好排序
  learning/      提交事件学习与统计清理
platform/windows/
  tsf/            TSF 生命周期、组合串与按键路由
  candidate-ui/   候选窗口和状态呈现
manager/
  entries/        词条增删改查、拖动排序
  backup/         JSON 导入导出
storage/
  migrations/     SQLite schema 与升级
```

目录是逻辑模块建议；正式实现时可根据选定的 Windows UI 技术调整。

## 11. 里程碑

1. **M0 设计确认**：确定 86 版五笔、全拼、首版 Windows 目标和默认按键方案。
2. **M1 引擎原型**：输入编码可查询词条，支持用户词条与稳定候选排序；提供调试界面。
3. **M2 词库管理**：实现添加、编辑、删除、置顶、拖动排序、导入导出。
4. **M3 个性学习**：记录提交频率与最近使用，支持清空学习记录，校准候选排序。
5. **M4 Windows 集成**：接入 TSF，完成常见文本框组合输入、候选确认、安装和卸载。
6. **M5 日常可用**：完善设置、备份恢复、错误提示和使用文档。

## 12. 首版验收标准

- 用户能在拼音和 86 五笔模式间切换，并在常见 Windows 文本框输入文字。
- 用户可新增一条同时含拼音/五笔编码的词条，并在两个模式中分别检索到它。
- 用户可新增只属于一种模式的词条；另一模式不会错误命中该编码。
- 用户能编辑、删除、置顶并调整词条顺序；重启后顺序仍保留。
- 对相同匹配质量的候选，多次选用的词会逐渐靠前；清空学习记录后恢复初始频率。
- 导出的词条可在空白配置中导入；非法文件不会造成部分写入。
- 输入和学习数据不需要网络连接即可使用。

## 13. 待实现前确认的默认约定

首版先按 Windows 11、86 版五笔、全拼、`Ctrl+Shift` 可配置切换、词库仅本地保存推进。快捷键必须允许用户修改，以免与系统或其他软件冲突。
